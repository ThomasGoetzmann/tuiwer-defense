Concept

A struct is a value, not a reference

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Position {
    pub x: u16,
    pub y: u16,
}

impl Position {
    pub fn new(x: u16, y: u16) -> Self {   // Self = Position
        Self { x, y }                       // field init shorthand
    }
}

pub struct Wallet {
    gold: u32,                              // private field
}

impl Wallet {
    pub fn gold(&self) -> u32 { self.gold }        // reads: &self
    pub fn earn(&mut self, amount: u32) {           // changes: &mut self
        self.gold = self.gold.saturating_add(amount);
    }
}

#[derive(Copy, Clone)] is for small, plain values. A Position is 4 bytes, so copying it is free. Chapter 3 explains what happens to types that are not Copy.

Exercise 1.3-A: Position and Map

Add two types to the domain crate:

  • Position, as above, with a method manhattan_distance(self, other: Position) -> u16: the number of grid steps between two positions.
  • Map with private fields: width: u16, height: u16 and path: Vec<Position>. Give it:
    • new(width, height, path) -> Self
    • width(&self) and height(&self) getters
    • contains(&self, pos: Position) -> bool: is the position inside the map?
    • is_on_path(&self, pos: Position) -> bool
    • path_len(&self) -> usize
fn small_map() -> Map {
    let path = vec![Position::new(0, 1), Position::new(1, 1), Position::new(2, 1)];
    Map::new(3, 3, path)
}

#[test]
fn manhattan_distance_counts_grid_steps() {
    let a = Position::new(1, 2);
    let b = Position::new(4, 0);
    assert_eq!(a.manhattan_distance(b), 5);
    assert_eq!(b.manhattan_distance(a), 5);
}

#[test]
fn positions_are_equal_by_value() {
    assert_eq!(Position::new(3, 4), Position { x: 3, y: 4 });
}

#[test]
fn map_contains_only_inside_positions() {
    let map = small_map();
    assert!(map.contains(Position::new(0, 0)));
    assert!(map.contains(Position::new(2, 2)));
    assert!(!map.contains(Position::new(3, 0)));
    assert!(!map.contains(Position::new(0, 3)));
}

#[test]
fn map_knows_its_path() {
    let map = small_map();
    assert!(map.is_on_path(Position::new(1, 1)));
    assert!(!map.is_on_path(Position::new(1, 0)));
    assert_eq!(map.path_len(), 3);
    assert_eq!((map.width(), map.height()), (3, 3));
}

vec![…] is a macro that creates a Vec with values, like a C# collection initializer.

Hint 1: direction

For the distance, you need the absolute difference of two unsigned numbers. Subtraction in the wrong order underflows.

Hint 2: concept

Integer types have an abs_diff method. A Vec has len() and contains(&value). contains takes a reference, so you write &pos. The PartialEq derive makes the comparison possible.

Hint 3: almost code

self.x.abs_diff(other.x) + self.y.abs_diff(other.y). For contains: pos.x < self.width && pos.y < self.height. For is_on_path: self.path.contains(&pos).

Compiler error of the day

Three small experiments. Undo each one before the next.

  1. In a test, create Position { x: 1 }. Read E0063: every field needs a value. There is no null and no default.
  2. In the TUI main, create a map and read map.width (the field, not the method). Read E0616: the field is private outside its module.
  3. Remove Copy from the derive of Position. Run the tests. Read E0382: use of moved value. manhattan_distance(self, …) took b away, so the second line cannot use it. This is ownership, the topic of chapter 3. Put Copy back.
Boss fight: newtypes

Lives and gold are both u32. Nothing stops lives -= tower_cost. Create a newtype pub struct Gold(u32); with methods can_afford(self, cost: Gold) -> bool and spend(&mut self, cost: Gold). Write tests first. Then think: should spend be allowed to fail? You will return to this in chapter 4.

C# link: this solves “primitive obsession”, like a readonly record struct Gold(uint Value). In Rust, the wrapper has zero runtime cost.

Why Rust does this

Rust has no inheritance on purpose. Deep class hierarchies create tight coupling and the “fragile base class” problem. Rust keeps data (struct), behaviour (impl) and contracts (trait) separate, and combines them freely. As an architect, you already prefer composition over inheritance. Rust makes it the only option.

Deep dive

You can have many impl blocks for one type, even in different files of the same crate. You can also print any Debug value in a nice layout with {:#?}, or quickly inspect a value with dbg!(&map.path_len()). dbg! prints the file, the line and the expression, and returns the value. Use it for debugging, and never commit it.
