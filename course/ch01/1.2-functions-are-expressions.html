F# again: in F#, everything is an expression and the last line is the result. Rust works the same way. The only new thing is the ;.

Concept

The semicolon throws the value away

fn reward(is_boss: bool) -> u32 {
    let base = if is_boss { 50 } else { 5 };   // if is an expression
    let bonus = {                               // a block is an expression
        let multiplier = 2;
        base * multiplier                       // no ; = the block's value
    };
    base + bonus                                // the function's value
}

return exists, but use it only for an early exit. The normal result is the last expression.

Both branches of an if must have the same type. An if without else has the type ().

Hands-on

Loops in two minutes

for wave in 1..=3 { println!("wave {wave}"); }   // 1, 2, 3  (..= includes the end)
for i in 0..3 { println!("index {i}"); }          // 0, 1, 2  (.. excludes the end)

let mut n = 0;
let first_big = loop {          // loop + break value = a value
    n += 7;
    if n > 30 { break n; }
};                              // first_big == 35
  1. Write this code in a test with --nocapture. Change ..= to .. and see the difference.
  2. Change break n to only break. The code still compiles. Hover over first_big in your editor (Neovim: K). What is its type now? Why?
Exercise 1.2-A: wave rules

Write three public functions in the domain crate. These are the rules:

  • enemies_in_wave(wave: u32) -> u32: wave 1 has 5 enemies. Each wave adds 2. Every 5th wave (5, 10, …) is a boss wave with only 1 enemy.
  • build_time_secs(wave: u32) -> u32: wave 1 gives 30 seconds. Each wave removes 2 seconds. Never less than 10.
  • total_enemies(up_to_wave: u32) -> u32: the sum of the enemies of waves 1 to up_to_wave. Use a for loop.
#[test]
fn normal_waves_grow_by_two() {
    assert_eq!(enemies_in_wave(1), 5);
    assert_eq!(enemies_in_wave(2), 7);
    assert_eq!(enemies_in_wave(4), 11);
    assert_eq!(enemies_in_wave(6), 15);
}

#[test]
fn every_fifth_wave_is_a_boss() {
    assert_eq!(enemies_in_wave(5), 1);
    assert_eq!(enemies_in_wave(10), 1);
}

#[test]
fn build_time_shrinks_to_a_minimum() {
    assert_eq!(build_time_secs(1), 30);
    assert_eq!(build_time_secs(2), 28);
    assert_eq!(build_time_secs(11), 10);
    assert_eq!(build_time_secs(50), 10);
}

#[test]
fn total_counts_all_waves() {
    assert_eq!(total_enemies(3), 5 + 7 + 9);
    assert_eq!(total_enemies(5), 5 + 7 + 9 + 11 + 1);
    assert_eq!(total_enemies(0), 0);
}
Hint 1: direction

Each rule is one if expression. Look again at build_time_secs(50): what happens with plain subtraction?

Hint 2: concept

“Every 5th” is a remainder: the % operator. Then run clippy: it suggests a more readable method. Accept it. For the build time, reuse what you learned in 1.1. For the total, you need a let mut accumulator and a range with ..=.

Hint 3: almost code

if wave.is_multiple_of(5) { 1 } else { 5 + (wave - 1) * 2 } is the shape of the first one. For the second, compute the reduction with saturating_sub, then apply .max(10).

Compiler error of the day

In enemies_in_wave, add a ; after the last expression. Run cargo build.

Read E0308: expected u32, found (). Find the help: remove this semicolon line. You will make this mistake often in the first week. Now you can recognise it in one second.

Boss fight

What does enemies_in_wave(0) return? Is wave 0 a valid input? Write a test that documents your decision. Then write total_enemies a second time, as one line, without mut. Search the std docs for Iterator::sum and Iterator::map. You will meet them properly in chapter 5.

Why Rust does this

Rust took “everything is an expression” from the ML family of languages (OCaml, and so F#). The first Rust compiler was written in OCaml. This is why Rust has no ternary operator: if already does the job.

Deep dive

Rust has no function overloading and no default parameters. In C#, Spawn(int count) and Spawn(int count, bool boss = false) can live together. In Rust you write spawn and spawn_boss, or you pass a struct with options. The reason: type inference works much better when one name has exactly one signature.
