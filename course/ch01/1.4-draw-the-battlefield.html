Concept

Two string types

The rule for now: return a String when you build new text. Accept a &str when you only read text. Chapter 3 explains why this works.

let mut row = String::with_capacity(8);   // like new StringBuilder(8)
row.push('S');
row.push_str("###");
row.push('\n');
let header = format!("Wave {wave:>2}/{MAX_WAVES} · Gold {gold:>4}");
Exercise 1.4-A: render the map

Add render_ascii(&self) -> String to Map. One character per tile, and \n after each row:

  • S: the first tile of the path (the spawn)
  • E: the last tile of the path (the exit)
  • #: any other path tile
  • .: an empty tile
#[test]
fn renders_a_straight_path() {
    let path = (0..5).map(|x| Position::new(x, 1)).collect();
    let map = Map::new(5, 3, path);
    assert_eq!(map.render_ascii(), ".....\nS###E\n.....\n");
}

#[test]
fn renders_a_bent_path() {
    let path = vec![
        Position::new(0, 0),
        Position::new(0, 1),
        Position::new(0, 2),
        Position::new(1, 2),
        Position::new(2, 2),
    ];
    let map = Map::new(3, 3, path);
    assert_eq!(map.render_ascii(), "S..\n#..\n##E\n");
}

The first test uses an iterator and a closure (|x| …) to build the path. You will write them yourself in chapter 5. For now, read it as “for x in 0..5, make a position”.

Hint 1: direction

Two nested for loops: rows (y) outside, columns (x) inside. Decide one character per tile.

Hint 2: concept

A Vec has first() and last(). They do not return a Position, because the list can be empty. They return an Option of a reference (chapter 4). You can still compare: self.path.first() == Some(&pos). An if … else if … else chain is an expression that gives a char.

Hint 3: almost code

let tile = if self.path.first() == Some(&pos) { 'S' } else if … { 'E' } else if self.is_on_path(pos) { '#' } else { '.' }; then out.push(tile);. After the inner loop: out.push('\n');. The capacity is (width + 1) * height.

Exercise 1.4-B: design the first level

Write a public function first_level() -> Map. You design the path. The rules: the map is 30 × 10, the path starts on the left edge, ends on the right edge, and has no gaps. Make it interesting: at least three turns.

The test needs a read-only view of the path. Add this method to Map. It returns a slice, a borrowed view of the Vec:

pub fn path(&self) -> &[Position] {
    &self.path
}
#[test]
fn first_level_has_a_valid_path() {
    let map = first_level();
    let path = map.path();
    assert_eq!((map.width(), map.height()), (30, 10));
    assert_eq!(path[0].x, 0, "the path must start on the left edge");
    assert_eq!(path[path.len() - 1].x, map.width() - 1, "the path must end on the right edge");
    for &pos in path {
        assert!(map.contains(pos), "{pos:?} is outside the map");
    }
    for pair in path.windows(2) {
        assert_eq!(pair[0].manhattan_distance(pair[1]), 1, "gap between {:?} and {:?}", pair[0], pair[1]);
    }
}
Hint 1: direction

A path is a list of straight segments. Build it with one let mut path = Vec::new(); and one loop per segment. Be careful not to push the corner tile twice.

Hint 2: concept

A range counts up only. To go left or up, reverse it: (2..15).rev(). Each loop calls path.push(Position::new(x, y)).

Hint 3: almost code

for x in 0..=10 { path.push(Position::new(x, 1)); } then for y in 2..=7 { path.push(Position::new(10, y)); } and so on. Each segment starts one tile after the previous corner.

Compiler error of the day

Change the return type of render_ascii to &str, and return &out. Read E0515 cannot return reference to local variable. The compiler tells you: you cannot return a view into a String that is dropped at the end of the function. In C#, the GC keeps it alive. In Rust, nobody would own it. This is why you return a String. Put it back.

Boss fight

Writing a path tile by tile is boring. Write Map::from_waypoints(width: u16, height: u16, waypoints: &[Position]) -> Map. It takes only the corners, for example [(0,1), (10,1), (10,7), (18,7)], and fills the straight lines between them. Rewrite first_level with it. Your 1.4-B test must still pass, and it now protects the refactor. What should happen when two waypoints are not on one line? Write a test for your decision.

Why Rust does this

Rust strings are always valid UTF-8. You cannot index them with s[3], because a char can use 1 to 4 bytes, so “the 4th character” is not a cheap operation. C# hides this with UTF-16, and emoji break it (surrogate pairs). Rust makes the cost visible: s.chars().nth(3) clearly walks the text.

Deep dive
