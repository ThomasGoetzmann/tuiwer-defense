Hands-on

Hello, cargo

  1. Create a scratch project outside the game repository:

    mkdir -p ~/sources/rust-scratch
cd ~/sources/rust-scratch
cargo new hello
cd hello
ls -a; ls src

  2. Open Cargo.toml. Read it. It has only a few lines:

    [package]
name = "hello"
version = "0.1.0"
edition = "2024"

[dependencies]

    The edition line selects the language rules. 2024 is the latest.

  3. Open src/main.rs, then run it:

    cargo run

    The first line of output shows Compiling hello. The second time, cargo does not compile again.

  4. Change main. Use a variable inside the format string:

    fn main() {
    let game = "Tuiwer Defense";
    let waves = 10;
    println!("Welcome to {game}! Survive {waves} waves.");
    println!("Debug view: {:?}", (game, waves));
}

    The ! in println! means it is a macro. The compiler checks the format string at compile time. A wrong placeholder name is a compile error, not a runtime error.

  5. Compare debug and release builds:

    cargo build
cargo build --release
ls -lh target/debug/hello target/release/hello
./target/release/hello

    The result is one native executable. There is no runtime to install, and no JIT.

  6. Try the fast feedback command. It checks types but does not build an executable:

    cargo check

    You will use cargo check (or an editor) many times per minute. It is much faster than build.

Each crate is compiled once and cached in target/. Only changed crates are compiled again.

Compiler error of the day

Add these two lines at the end of main, then run cargo run:

    let lives = 20;
    lives = lives - 1;

Read the full error. Look for four things:

  1. The error code, for example E0384.
  2. The arrows that point at your code.
  3. The help line. It often contains the fix.
  4. The rustc --explain suggestion.
rustc --explain E0384

Do what the help line says. The program must compile again. You just met the first big rule: variables are immutable by default. Lesson 1.1 explains it.

Exercise 0.2-A

Add a dependency and use it. Make the program print the welcome text in colour.

cargo add owo-colors

Find how to use the crate. Do not ask the AI for the code. Use these sources, in this order:

  1. The crate page on docs.rs. Every crate has docs there.
  2. The examples on that page.
Hint 1: direction

The crate adds methods to strings. You need to bring a trait into scope with use.

Hint 2: concept

In Rust, a method from a trait is visible only when the trait is in scope. This is like C# extension methods: you need the using for the namespace. The docs.rs front page shows the use line.

Hint 3: almost code

use owo_colors::OwoColorize; then call a colour method like .green() on the text inside println!. Note: the crate name has a -, but in code it is _.

Check 
cargo run

The welcome text appears in colour. Then look at Cargo.lock: it lists the exact version of owo-colors.

Why Rust does this

Rust compiler errors are famous for being helpful. This is a deliberate project goal: the compiler team treats a confusing error message as a bug. When you are stuck, read the whole message first. In Rust, the compiler is your first teacher.
