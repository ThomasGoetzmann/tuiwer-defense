Concept

The target layout

tuiwer-defense/
├── Cargo.toml              ← workspace (like the .sln)
├── Cargo.lock              ← one lock file for all crates
├── crates/
│   ├── tuiwer-domain/      ← library: rules, no I/O
│   │   ├── Cargo.toml
│   │   └── src/lib.rs
│   └── tuiwer-tui/         ← binary: terminal + main()
│       ├── Cargo.toml
│       └── src/main.rs
├── course/                 ← this course
└── target/                 ← build output (ignored by git)
flowchart LR
    tui["tuiwer-tui (bin)"] -- "depends on" --> domain["tuiwer-domain (lib)"]
    domain -. "cannot see" .-> tui

The domain crate does not list the TUI crate as a dependency. So the domain cannot use TUI code. In C#, you need architecture tests or discipline for this. In Rust, the build fails.

Hands-on

Build the skeleton

  1. Go to the repository. It already contains git, the course and a .gitignore.

    cd ~/sources/tuiwer-defense
git status

  2. Create the root Cargo.toml. Type it yourself. Read each line while you type:

    [workspace]
resolver = "3"
members = ["crates/*"]
default-members = ["crates/tuiwer-tui"]

[workspace.package]
version = "0.1.0"
edition = "2024"
license = "MIT"

[workspace.lints.rust]
unsafe_code = "forbid"
    • resolver = "3": the dependency resolver for edition 2024. A workspace must set it.
    • members: every folder in crates/ is part of the workspace.
    • default-members: cargo run in the root starts the TUI.
    • [workspace.package]: values that crates can inherit.
    • unsafe_code = "forbid": no unsafe code in this project. Chapter 17 explains why it exists.

  3. Create the two crates:

    cargo new --lib crates/tuiwer-domain
cargo new crates/tuiwer-tui

    Cargo sees the existing git repository. It does not create a second one.

  4. Open crates/tuiwer-domain/Cargo.toml. Cargo found the workspace and wrote inheritance lines for you:

    [package]
name = "tuiwer-domain"
version.workspace = true
edition.workspace = true
license.workspace = true

[dependencies]

[lints]
workspace = true

    version.workspace = true means “use the value from [workspace.package]”. Change the version in one place, and all crates follow. This is Directory.Build.props, without the XML.

  5. Make the TUI depend on the domain:

    cargo add --package tuiwer-tui --path crates/tuiwer-domain

    Open crates/tuiwer-tui/Cargo.toml and find the new line.

  6. Build everything and run the tests that cargo new generated:

    cargo build --workspace
cargo test --workspace

    Look at the generated test in crates/tuiwer-domain/src/lib.rs. The #[cfg(test)] line means: compile this module only for tests.

Exercise 0.3-A

Replace the generated code in tuiwer-domain/src/lib.rs with a public function game_title. It returns the text "Tuiwer Defense". Start with this test. It must fail first (red), then pass (green):

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn title_is_tuiwer_defense() {
        assert_eq!(game_title(), "Tuiwer Defense");
    }
}

Then make main in the TUI crate print the title, using tuiwer_domain::game_title().

Hint 1: direction

A function is private by default. The TUI crate needs to see it.

Hint 2: concept

The keyword pub makes an item public. The return type of a text literal is &'static str: a borrowed string that lives for the whole program. Chapter 3 explains & and chapter 10 explains 'static. For now, read it as “a fixed text”.

Hint 3: almost code

pub fn game_title() -> &'static str { … }. The body is only the text literal, with no return and no ;. In main: println!("{}", tuiwer_domain::game_title());. Note the crate name uses _ in code.

Check 
cargo test --workspace; and cargo run

One test passes. The program prints Tuiwer Defense. Commit:

git add -A
git commit -m "Create workspace with domain and tui crates"
Compiler error of the day

Prove that the architecture rule works. Add this line at the top of tuiwer-domain/src/lib.rs:

use tuiwer_tui;

Run cargo build. Read error E0432. The domain cannot see the TUI crate. Now try to make it a dependency anyway:

cargo add --package tuiwer-domain --path crates/tuiwer-tui

Cargo adds the line. Now run cargo build again. Read the error: cyclic package dependency. A cycle is never allowed between crates. Undo both changes:

cargo remove --package tuiwer-domain tuiwer-tui
git diff

Also remove the use line. git diff must show only your exercise changes.

Deep dive

Rust has three kinds of tests:

  • Unit tests in a #[cfg(test)] mod tests inside the source file. They can test private functions.
  • Integration tests in a tests/ folder. They see only the public API. Chapter 12.
  • Doc tests: code examples in /// comments. Cargo runs them. Chapter 8.

As a testing expert, you will like this: there is no test framework to choose. cargo test is the framework.
