Each step catches problems the step before can miss. The CI is the gate: nothing reaches main red.

Hands-on

Format and lint

  1. Break the format on purpose. In main.rs, put all code on one line with odd spaces. Then:

    cargo fmt --check
cargo fmt
git diff

    --check only reports. Without it, cargo fmt fixes the files. Your editor also formats on save (RustRover: Settings → Rust → Rustfmt → Run on save).

  2. Add this function to the domain crate, then run clippy:

    pub fn is_game_over(lives: u32) -> bool {
    if lives == 0 { return true; } else { return false; }
}
    cargo clippy --workspace --all-targets

    Read the warning. Each warning has a link to an explanation. Fix the code the way clippy suggests. Then decide: do you need this function? If not, delete it.

  3. Install the two helper tools. cargo install compiles them from source. This takes a few minutes:

    cargo install --locked bacon cargo-nextest

    The binaries go into ~/.cargo/bin, which is already on your PATH.

  4. Open a second terminal (or a Herdr pane) in the repository and start bacon:

    bacon

    Press c for clippy, t for tests, h for help. Change some code and save. Watch bacon react. Keep bacon open during all lessons.

  5. Try nextest:

    cargo nextest run --workspace
Exercise 0.4-A: CI on GitHub

Create .github/workflows/ci.yml with three gates: format, clippy (warnings are errors) and tests. Use these building blocks:

  • actions/checkout@v4
  • dtolnay/rust-toolchain@stable with components: clippy, rustfmt
  • Swatinem/rust-cache@v2 (caches target/ between runs)
Hint 1: direction

One job on ubuntu-latest is enough. Run it on push to main and on pull requests.

Hint 2: concept

You need three run steps after the setup steps. Use --workspace so all crates are checked. For clippy, use --all-targets so tests are linted too, and pass -- -D warnings.

Hint 3: almost code

The three commands: cargo fmt --all --check, cargo clippy --workspace --all-targets -- -D warnings, cargo test --workspace. The toolchain step uses with: for components.

Then publish the repository. This makes it visible on GitHub, so check the content first:

git status
git add -A
git commit -m "Add CI"
gh repo create tuiwer-defense --public --source . --push

Use --private if you prefer. You can change it later.

Check 
gh run watch

The run is green. Then break the format in a small commit, push, and watch the run fail. Fix it, push again.

Show-off

Add a CI badge to the top of README.md. Replace OWNER with your GitHub name:

![CI](https://github.com/OWNER/tuiwer-defense/actions/workflows/ci.yml/badge.svg)

A green badge on day one. Keep it green for the whole course.

Boss fight

Turn on the stricter clippy::pedantic group for the workspace. Add this to the root Cargo.toml:

[workspace.lints.clippy]
pedantic = { level = "warn", priority = -1 }

Some pedantic lints are noisy. Find one lint you disagree with, and allow it in the same section with a comment that explains why. Decide if you keep pedantic for the course. Both answers are fine. The point is to know that you can choose.

Why Rust does this

rustfmt has almost no options on purpose. Code style arguments waste time, so the community chose one style for everybody. When you read any Rust project on GitHub, it looks familiar. Go did the same with gofmt, and Rust copied the idea.
