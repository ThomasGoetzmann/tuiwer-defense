Appendix A: Neovim for Rust

What each line of the Rust setup does, why it is there, and what you see without it. The setup uses your existing config in ~/sources/dotfiles-v2. It adds no new plugins.

Goal
  • Completion, errors, hover docs and refactors from rust-analyzer.
  • Format on save with rustfmt.
  • Syntax highlighting with treesitter.
  • A debugger with codelldb.

The important decision: rust-analyzer and rustfmt come from rustup, not from mason. rustup installs them with your compiler. They always have the same version as rustc. A mason copy can be older or newer than your compiler, and that gives strange errors in macros and new syntax.

The five changes

1. The chezmoi script installs Rust with rustup

File: .chezmoiscripts/run_onchange_after_30-serie.sh.tmpl

# Rust toolchain: always through rustup (never brew's standalone rust).
# --no-modify-path: fish config already adds ~/.cargo/bin.
if ! command -v rustup >/dev/null; then
  curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --no-modify-path
fi
export PATH="$HOME/.cargo/bin:$PATH"
rustup default stable
rustup component add rust-analyzer rust-src clippy rustfmt
  • Why: before, the script ran brew install rust on a new machine. Brew's Rust has no rustup, so you cannot add components or switch versions.
  • --no-modify-path: the installer does not edit shell files. Your fish config already has fish_add_path -p ~/.cargo/bin.
  • export PATH=…: the script itself runs in bash, so it needs the path for the next lines.
  • rust-src: the source code of the standard library. rust-analyzer needs it for completion and go-to-definition into std.
  • On this machine, rustup is already installed. The script only makes sure the components are present.

2. Start rust-analyzer

File: lua/tg/plugins/lsp/lspconfig.lua, at the end of config

-- rust-analyzer comes from rustup (matches the compiler), not mason
vim.lsp.enable("rust_analyzer")
  • What: Neovim 0.12 has a built-in LSP client. vim.lsp.enable starts a server when you open a matching file. The server settings (command, file types, root markers) come from nvim-lspconfig, which you already have.
  • Why it is needed: your other servers start automatically because mason-lspconfig enables everything that mason installed. rust-analyzer does not come from mason, so you enable it yourself.
  • Without it: no completion, no errors in the editor, and K shows nothing.
  • Your existing LspAttach keymaps work for Rust too: gd, gR, K, <leader>;, <leader>rn.

Never install rust-analyzer in :Mason. mason-lspconfig would then start a second copy, and you would see every error twice.

3. Format on save

File: lua/tg/plugins/formatting.lua

rust = { "rustfmt" },
  • What: conform runs rustfmt on save. Your config already has format_on_save.
  • Edition: conform reads the edition from Cargo.toml. It understands edition.workspace = true and finds 2024 in the workspace root.
  • Without it: the code is still formatted, because your config uses lsp_format = "fallback" and rust-analyzer can format. The explicit line makes the choice visible and does not depend on the LSP being ready.

4. Syntax highlighting

File: lua/tg/plugins/treesitter.lua

"vimdoc", "c", "nu", "rust", "toml",
  • rust: highlighting, indentation and text objects for .rs files.
  • toml: for Cargo.toml.
  • rust-analyzer also sends semantic tokens (for example, it colours mutable variables differently). Treesitter gives the fast base colours. Both work together.

5. The debugger

File: lua/tg/plugins/dap.lua

ensure_installed = { "netcoredbg", "codelldb" },
  • What: mason installs codelldb, a debug adapter for LLDB. It works for Rust, C and C++.
  • Why no more config: your config has handlers = {}. mason-nvim-dap then creates default launch configurations, like it does for netcoredbg.
  • The default configuration asks for the path to executable. Type target/debug/tuiwer-tui.
Hands-on

Apply and test

  1. Look at what chezmoi will change, then apply:

    chezmoi diff
chezmoi apply

    The serie script runs again because its content changed. This is normal.

  2. Start Neovim. lazy.nvim installs the parsers, and mason installs codelldb. Wait until both are done (:Lazy, :Mason).

  3. Open a Rust file in the game repository. Check the LSP:

    :checkhealth vim.lsp

    You must see rust_analyzer attached, with the command from ~/.cargo/bin. The first start indexes the standard library. This takes some seconds.

  4. Test the features:

    • Hover a type with K.
    • Write let x: u32 = "a"; and see the error inline. Delete it.
    • Break the indentation, then save. The file is formatted.
    • On a function name, use <leader>rn to rename it everywhere.

  5. Test the debugger:

    cargo build

    Set a breakpoint in main with <leader>db. Start with <leader>dc, choose LLDB: Launch, and enter target/debug/tuiwer-tui. Use <leader>du for the DAP UI.

    To debug a unit test, run cargo test --workspace --no-run. Cargo prints the path of each test executable in target/debug/deps/. Use that path instead.
