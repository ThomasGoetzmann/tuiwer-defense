LEARN RUST · BUILD A GAME

Tuiwer Defense

A Rust course for C# developers. You learn the language while you build a tower defense game that runs in your terminal.

Your progress

Each lesson page has a Mark lesson as done button at the bottom. The browser keeps your progress. If you run python3 course/serve.py and open http://localhost:8000, the progress also goes to course/.progress.json. Git ignores that file.

How this course works

  • A chapter takes 1 to 2 hours. A lesson takes 15 to 25 minutes.
  • You write all the game code. The lessons give you goals, tests and hints. They do not give full solutions.
  • Each exercise has a check: a command that must be green before you continue.
  • Commit after each exercise. When you finish a lesson, ask your AI tutor for a review (see Use AI as a tutor).
  • Lessons are independent pages. If a lesson is too large, split it. If two are easy, do them together.

What you will build

Tuiwer Defense is turn based. In the build phase, a timer counts down and you place towers. Press Start to begin the wave early. In the wave phase, enemies walk along a fixed path and your towers shoot them. If too many enemies reach the end, you lose.

The architecture

The game uses a clean architecture. The domain does not know about the terminal or about files. Cargo enforces the dependency direction: a crate can only use the crates it lists.

flowchart LR
    tui["tuiwer-tui
presentation + main
(ratatui, crossterm)"]
    infra["tuiwer-infra
adapters: files, saves
(serde) — from chapter 13"]
    domain["tuiwer-domain
rules, Commands, ports
no I/O, fully tested"]
    tui --> domain
    tui --> infra
    infra --> domain

The domain is deterministic. The presentation layer calls game.apply(command) for player actions and game.tick() to move time forward. Random numbers come from a seeded generator. This makes tests repeatable, and it makes future features (build during a wave, a hero you control, a GUI) possible without domain rewrites.

Use AI as a tutor

The repository has a CLAUDE.md file. It tells Claude to teach, not to write your game code. Good requests are specific and ask for understanding:

Explain this compiler error. Do not fix it. Ask me a question that leads me to the fix.
Review my commits for lesson 1.3. Focus on idiomatic Rust. Compare with how I would do it in C#.
Give me hint level 2 for exercise 1.4-A. Do not show code.
Generate chapter 2. Read my current code first.

If the AI writes the code, you do not learn it. The compiler errors are the course. Ask for code only when you already solved the problem and want to compare.
